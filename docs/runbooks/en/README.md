# Runbooks

These runbooks explain how a tech lead can apply each GitHub Copilot scenario inside a real engineering environment.

| Runbook | Use it when |
| --- | --- |
| [01 - Engineering Metrics](01-engineering-metrics-runbook.md) | You want to measure Copilot adoption and pull request flow across teams or repositories. |
| [02 - Pull Request Review and Quality](02-pr-review-quality-runbook.md) | You want to improve PR review consistency, speed, and quality. |
| [03 - Technical Standards and Architecture Governance](03-standards-architecture-runbook.md) | You want to scale architecture and engineering standards across repositories. |
| [04 - Onboarding and Knowledge Transfer](04-onboarding-knowledge-runbook.md) | You want to onboard engineers faster and reduce repeated knowledge-transfer work. |

## Recommended adoption sequence

1. Start with **Engineering Metrics** to establish a baseline.
2. Use **Pull Request Review and Quality** to improve day-to-day execution.
3. Add **Technical Standards and Architecture Governance** to reduce repeated feedback.
4. Use **Onboarding and Knowledge Transfer** to scale learning and reduce tech lead bottlenecks.

## Common prerequisites

- GitHub Copilot enabled for the target users.
- GitHub CLI installed and authenticated where automation is needed.
- Access to the target repositories.
- Agreement on privacy boundaries for metrics and AI-assisted analysis.
- A team communication channel to share outcomes, actions, and improvements.
