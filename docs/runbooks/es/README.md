# Runbooks

Estos runbooks explican cómo un tech lead puede aplicar cada escenario de GitHub Copilot dentro de un entorno real de ingeniería.

| Runbook | Úsalo cuando |
| --- | --- |
| [01 - Métricas de Ingeniería](01-engineering-metrics-runbook.md) | Quieres medir la adopción de Copilot y el flujo de pull requests en equipos o repositorios. |
| [02 - Revisión de Pull Requests y Calidad](02-pr-review-quality-runbook.md) | Quieres mejorar la consistencia, velocidad y calidad de las revisiones de PR. |
| [03 - Estándares Técnicos y Gobierno de Arquitectura](03-standards-architecture-runbook.md) | Quieres escalar estándares de arquitectura e ingeniería entre repositorios. |
| [04 - Onboarding y Transferencia de Conocimiento](04-onboarding-knowledge-runbook.md) | Quieres incorporar ingenieros más rápido y reducir trabajo repetitivo de transferencia de conocimiento. |

## Secuencia de adopción recomendada

1. Comienza con **Métricas de Ingeniería** para establecer una línea base.
2. Usa **Revisión de Pull Requests y Calidad** para mejorar la ejecución diaria.
3. Agrega **Estándares Técnicos y Gobierno de Arquitectura** para reducir feedback repetido.
4. Usa **Onboarding y Transferencia de Conocimiento** para escalar el aprendizaje y reducir cuellos de botella del tech lead.

## Prerrequisitos comunes

- GitHub Copilot habilitado para los usuarios objetivo.
- GitHub CLI instalado y autenticado cuando se necesite automatización.
- Acceso a los repositorios objetivo.
- Acuerdo sobre límites de privacidad para métricas y análisis asistido por IA.
- Un canal de comunicación del equipo para compartir resultados, acciones y mejoras.
