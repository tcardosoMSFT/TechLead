# Scenario 4: Onboarding and Knowledge Transfer

## Goal

Use GitHub Copilot to help new developers understand codebases, flows, tests, and operational practices faster.

## Tech lead workflow

1. Ask Copilot to explain the main modules and runtime flow.
2. Generate onboarding walkthroughs for important features.
3. Ask for dependency maps and test entry points.
4. Create starter tasks with clear learning outcomes.
5. Keep onboarding documentation updated as the system evolves.

## Recommended prompts

```text
Explain this repository to a new engineer. Focus on the main runtime flow, key modules, local development commands, test strategy, and the safest first contribution.
```

```text
Create a 30-minute onboarding walkthrough for this feature, including files to read, concepts to understand, and a small safe change to make.
```

## Success indicators

- Faster first pull request from new team members.
- Fewer repeated onboarding questions.
- Better shared understanding of legacy code.
- More confidence when changing critical flows.
